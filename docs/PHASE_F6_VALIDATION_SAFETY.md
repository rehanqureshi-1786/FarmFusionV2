# Phase F6: Validation & Safety Node

## Executive Summary

The **Validation & Safety Node** (`app/orchestrator/nodes/validation.py`) executes deterministically between tool execution/RAG grounding and LLM response synthesis. It acts as an unbreakable safety barrier ensuring that:
1. An immutable **Verified Fact Set** is compiled from verified specialist tool payloads.
2. Physical and agronomic numerical bounds are strictly verified.
3. Cross-tool consistency (e.g. Weather rain vs Smart Irrigation advice) is guaranteed.
4. Confidence tiering obeys FarmFusion Safety Rule #3.
5. All generated responses pass the **Numerical Immutability Guard** before client emission.

---

Before any response synthesis occurs, the validator extracts machine-readable ground truth:

## 2. Agronomic Range & Integrity Checks

The validator verifies physical constraints across all extracted parameters:

| Parameter | Allowed Physical Range | Failure Severity | Action on Violation |
| :--- | :--- | :--- | :--- |
| **Air Temperature** | `-20.0°C` to `+65.0°C` | `BLOCKING` | Rejects payload, invalidates state |
| **Relative Humidity** | `0.0%` to `100.0%` | `BLOCKING` | Rejects payload |
| **Mandi Price** | `> 0.0 INR/quintal` | `BLOCKING` | Rejects payload |
| **Disease / Crop Probability** | `0.0` to `1.0` | `BLOCKING` | Rejects payload |
| **Tool Execution Status** | Successful execution | `BLOCKING` | Halts execution if blocking task failed |

---

## 3. Cross-Tool Consistency Verification

When multiple specialist tools execute in a multi-capability plan (e.g. Weather + Smart Irrigation), their outputs are compared for agronomic coherence:

- **Rule**: If Weather forecast predicts precipitation probability `>= 75%` while Smart Irrigation tool advises `WATER_NOW`:
  - Flag `cross_tool_consistency.consistent = False`.
  - Issue warning: *"Weather forecast predicts heavy rainfall probability (85%), which conflicts with immediate irrigation recommendation."*
  - The synthesizer is instructed to highlight caution and advise against field waterlogging.

---

## 4. Confidence Tiering (Safety Rule #3)

Model confidence is mapped to 4 discrete tiers:

| Confidence Score Range | Tier Classification | Required Wording Style |
| :--- | :--- | :--- |
| `>= 0.75` | `HIGH` | Authoritative confirmed assertion: *"पत्ती की जांच के अनुसार फसल में..."* |
| `0.45 – 0.74` | `MEDIUM` | Tentative model indication: *"मॉडल के अनुसार फसल में... होने की संभावना है"* |
| `0.30 – 0.44` | `LOW` | Cautious caveat with re-test advice: *"आंशिक लक्षण दिख रहे हैं, लेकिन विश्वसनीयता कम है"* |
| `< 0.30` | `UNCLEAR` | Rejection of diagnosis: *"बीमारी की स्पष्ट पहचान नहीं हो सकी, कृपया साफ फोटो लें"* |

## 5. Numerical Immutability Guard

After candidate text is generated by the LLM (or retrieved from templates):
1. All numerical values and currency amounts are parsed via regex (`verify_numerical_immutability`).
2. Numbers are matched against the verified factual set.
3. If an altered or invented value is detected (e.g. `₹2300` when verified price is `₹2260`):
   - The response is **rejected**.
   - One correction retry is triggered with the exact violation details.
   - If retry fails: **Deterministic Safe Synthesizer** is used immediately.

---

## 6. Deterministic Final Confidence Aggregation Policy (Fix 4)

To prevent arbitrary or hardcoded confidence scores (e.g., hardcoded `0.95`), the orchestrator applies a mathematical confidence aggregation formula:

$$\text{Confidence}_{\text{final}} = \min(\text{Intent Confidence}, \text{Specialist Model Confidence}) \times F_{\text{RAG}} \times F_{\text{Validation}} \times F_{\text{Freshness}}$$

Where:
- **Base Confidence**: $\min(C_{\text{intent}}, C_{\text{model}})$. If no ML model was executed (e.g. pure navigation or database lookup), the base defaults to $C_{\text{intent}}$.
- **RAG Factor ($F_{\text{RAG}}$)**:
  - `HIGH_EVIDENCE`: `1.0` (strong retrieval match, high similarity)
  - `MEDIUM_EVIDENCE`: `0.90`
  - `LOW_EVIDENCE`: `0.75`
  - `CONFLICTING`: `0.50`
  - No RAG needed/executed: `1.0`
- **Validation Factor ($F_{\text{Validation}}$)**:
  - Validation Passed (`is_valid = True`, warnings = 0): `1.0`
  - Minor Non-Blocking Warnings: `0.85`
  - Invalid / Blocked: `0.20`
- **Freshness Factor ($F_{\text{Freshness}}$)**:
  - Live data from API/Sensors/DB: `1.0`
  - Stale cache (> 24 hours): `0.90`
- **Immutability Invariant**: If underlying specialist model confidence is $\le 0.30$ (`UNCLEAR`), $\text{Confidence}_{\text{final}}$ is strictly bounded $\le C_{\text{model}}$ and will never be inflated.

## 7. Contradictory Disease Detection & Rejection (Fix 2)

Specialist agricultural pipelines can produce contradictory intermediate signals (e.g. Leaf/Pathogen classifier predicts *Tomato Mosaic Virus*, but Gatekeeper indicates `is_plant = False` or `healthy = True`).

The validation node executes `check_disease_contradictions`:
- If `is_plant == False` and disease is diagnosed: marked **INVALID / BLOCKING**.
- If `is_healthy == True` with high confidence and disease is predicted: marked **INVALID / BLOCKING**.
- When invalidation occurs, response synthesis refuses confident diagnosis, sets `confidence_tier = UNCLEAR`, and emits a structured recovery action:
  - `action = "REQUEST_INPUT"`
  - `destination = "DISEASE_SCAN"`
  - `required_input = "LEAF_IMAGE"`
  - `response_text = "विरोधाभासी संकेत मिले हैं... कृपया अच्छी रोशनी में पत्ती की साफ फोटो दोबारा लें।"`

---

## 8. Time-Horizon Grounding (Fix 5)

Farmer queries frequently target specific forecast horizons. The system explicitly parses and preserves four canonical horizons:
- `CURRENT`: Current observation (today's temperature, immediate weather)
- `24_HOURS`: 1-day advisory
- `48_HOURS`: 2-day forecast
- `7_DAYS`: Multi-day / Weekly disaster risk and precipitation forecast

The horizon is extracted in `extract_forecast_horizon`, recorded in the `VerifiedFactSet` under `forecast_horizon`, and verified in the final natural language response. For disaster queries spanning 7 days, responses explicitly state the 7-day scope without collapsing into single-day current weather.

---

## 9. Model Provenance & Identity Invariants (Fix 6)

Every tool output and trace must report the exact model actually executed:
- **Crop Recommendation**: Mode A runs `XGBoost` (trained classifier). Mode B runs `ICAR/FAO Agronomic Rules`. It must **never** report `LightGBM`.
- **Mandi Intelligence**: Current price uses `Agmarknet Historical Observation` / live API. 7-day price forecasting runs `Prophet + LightGBM Ensemble`.
- **Disaster Risk**: Multi-hazard risk scoring runs `Random Forest / Rule Matrix`.
- **Disease Detection**: Visual pathology runs `EfficientNet-B3` (fine-tuned on PlantVillage + PlantDoc).
- **RAG Embeddings**: Runs `sentence-transformers/all-MiniLM-L6-v2` (384-dimensional zero-padded to 1024 pgvector HNSW index).

## 10. Phase F6 Golden Verification Suite

The hardening test suite (`backend/tests/test_f6_hardening_golden.py`) verifies the 10 critical end-to-end golden paths:
1. Low-confidence disease (confidence 0.14 remains $\le 0.14$, tier UNCLEAR)
2. Healthy-vs-disease contradiction rejection and safe photo re-request
3. Mandi compound intent (Hindi, Hinglish, English) producing `[CURRENT_PRICE, MANDI_FORECAST, MANDI_DECISION]`
4. 7-day disaster query preserving `7_DAYS` horizon
5. High-confidence disease confirming diagnosis with verified RAG package of practices
6. Low-confidence disaster preserving `LOW` risk without false alarms
7. Multi-tool weather + irrigation cross-tool verified advice
8. Composite disease + weather + RAG execution
9. Mandi current + forecast + decision numerical consistency
10. Missing leaf image navigating to `DISEASE_SCAN` with `required_input = "LEAF_IMAGE"`
11. Tool contract model identity verification
12. Numerical immutability guard against altered prices, temperatures, or risk levels
